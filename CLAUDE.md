# Прописи HSK

Статический PWA-тренажёр иероглифов. Сборки нет: файлы из корня репозитория как есть публикуются на GitHub Pages (ветка `main`, папка `/`) — https://github.com/Kritic000/hsk-trainer → https://kritic000.github.io/hsk-trainer/.

- `index.html` — всё приложение (разметка, стили, скрипт, словарь `META`). Внизу четыре раздела: «Знаки» (список группы → прописи, «Правила»), «Речь» (тренер, диалоги, фразы, «Мои диалоги»), «Повтор» (цель дня и серия дней, «Узнай знак» и фразы по интервалам, знаки с ошибками, трудные; диапазон уроков), «Ещё» (оформление, микрофон, отладка, офлайн, источники). Тема и узор фона — ключи `hsk-propisi-v2-theme` и `-pattern`; интервалы знаков — `-csrs`, похожих знаков — `-ssrs` (у фраз свой `-srs`), «подсматривал» при чтении без пиньиня — `-peek`, цель дня и серия — `-goal`, `-goalday`, `-streak`.
- `sw.js` — service worker: кэш оболочки (`SHELL_VERSION`) и кэш данных (`DATA_VERSION`).
- `data/*.json` — черты, озвучка и примеры предложений (`sentences-N.json`) по уровням; `lib/` — hanzi-writer; `fonts/` — локальные шрифты; `icons/`, `manifest.json` — PWA.
- `data/hints-1.json` — карточки знаков HSK 1 (части и короткая подсказка) и группы похожих знаков. Не править руками: источник — `tools/hints/hsk1.tsv` и `tools/hints/similar.txt`, сборка `npm run hints`. Файл входит в оболочку (`SHELL_FILES`), при изменении — `SHELL_VERSION += 1`. Новые знаки в текстах — проверить `npm run font-gap`.
- `data/speech-N.json` — свои диалоги и опорные фразы раздела «Речь» по урокам. Не править руками: источник — `tools/speech/hskN.txt`, сборка `npm run speech` (проверяет знаки по урокам и сверяет с `exclude.txt`). Уровень с таким файлом должен быть в `SPEECH_IDS` в `index.html`.
- `data/voice-N.json`, `data/voice-N-УУ.mp3` — озвучка фраз уровня нейросетевым голосом (Kokoro-82M-v1.1-zh, голос zf_017). Не править руками: сборка `python tools/voice.py N` после изменения диалогов, фраз, слов или примеров уровня. Уровень с такими файлами должен быть в `VOICE_IDS` в `index.html`. Всё, чего нет в указателе, читает синтез речи телефона.
- `lib/sherpa/` — строгая проверка по записи в «Речи»: распознавание записи на устройстве (sherpa-onnx WASM в воркере `asr-worker.js`). Движок и модель (≈75 МБ) не в репозитории: скачиваются с Hugging Face по адресам `ASR_FILES` в `index.html`, когда пользователь включает режим, и лежат в кэше `propisi-asr-v1` (в `sw.js` он в списке сохраняемых — не удалять). Записи и распознанный текст никуда не отправляются.
- `asr-test/` — отдельная тестовая страница распознавания речи по записи прямо в браузере (sherpa-onnx WASM, Whisper), адрес `/asr-test/`. В приложение не встроена: свой service worker (`asr-test/sw.js`), модели качаются с Hugging Face в кэш браузера; `sw.js` приложения запросы к `/asr-test/` не трогает. Версии кэша приложения при её правке поднимать не нужно.
- `CREDITS.md` — источники и лицензии всего чужого (данные, библиотеки, шрифты, модели); короткая версия — в «Ещё» → «Источники». Добавил или заменил что-то чужое — допиши туда и туда.
- `tools/` — сборка примеров предложений и шрифтов (Node.js), см. `tools/README.md`. `data/sentences-*.json` не править руками — только через `tools/sentences/` и `npm run build`. Правила отбора (HSK 1 — по урокам Standard Course 1, HSK 2–6 — слова своего уровня) описаны там же.
- Прогресс пользователя хранится в localStorage под ключами `hsk-propisi-v2-*` — не менять ключи и формат без миграции. «Мои диалоги» раздела «Речь» — только в IndexedDB (`propisi-speech`) на устройстве: в репозиторий и на сервер не отправлять. Записи голоса ученика («Записать себя», кнопка микрофона) — тоже только на устройстве, в IndexedDB `propisi-rec` (три последние попытки на фразу, не больше 12 МБ): никуда не отправлять. Там же (хранилище `debug`) — записи режима отладки распознавания, последние 20 попыток; текст лога — в localStorage `hsk-propisi-v2-dbglog`.

## Обязательно после каждой завершённой доработки

1. **Поднять версии кэша в `sw.js`**, если менялись соответствующие файлы:
   - `lib/`, `fonts/`, `icons/`, `manifest.json`, `sw.js` или список `SHELL_FILES` → `SHELL_VERSION += 1`. Вместе с ним — то же число в `APP_VERSION` в `index.html`: оно показано внизу разделов «Речь» и «Ещё», по нему пользователь видит, что приложение обновилось.
     (`index.html` загружается по сети в первую очередь, но при его изменении тоже поднимай `SHELL_VERSION`, чтобы офлайн-копия обновилась сразу.)
   - Изменились уже опубликованные `data/strokes-*.json` или `data/audio-*.json` → `DATA_VERSION += 1` **и** то же число в `DATA_CACHE` в `index.html` (`"propisi-data-vN"`). Это заставит пользователей заново скачать ~21 МБ — только при реальных изменениях.
   - Изменились опубликованные `data/sentences-*.json` → `SENT_VERSION += 1` **и** то же число в `SENT_CACHE` в `index.html` (`"propisi-sent-vN"`). Новые файлы данных версию не требуют.
   - Изменились опубликованные `data/speech-*.json` → `SPEECH_VERSION += 1` **и** то же число в `SPEECH_CACHE` в `index.html` (`"propisi-speech-vN"`).
   - Изменились опубликованные `data/voice-*` → `VOICE_VERSION += 1` **и** то же число в `VOICE_CACHE` в `index.html` (`"propisi-voice-vN"`).
   - Менялись данные HSK 1 в `tools/hsk1/items.tsv` → `npm run hsk1` (пишет в `index.html`), значит и `SHELL_VERSION`.
   - Добавил новый файл оболочки — внести его в `SHELL_FILES`.
2. **Закоммитить** с понятным описанием на русском: что изменилось для пользователя, в повелительном или прошедшем времени, например `Добавлен поиск по ключам` / `Исправлена озвучка слов в HSK 3`.
3. **Сделать `git push` в `main`** — GitHub Pages опубликует сайт сам за 1–2 минуты.

Не коммитить временные файлы, профили браузеров и скриншоты проверок.
