# Инструменты: примеры предложений и шрифты

Собирают `data/sentences-1…6.json` (примеры к каждому знаку) и `fonts/`. Нужен только Node.js 18+.

```
cd tools
npm install          # один раз: pinyin-pro (пиньинь) и seek-bzip (распаковка выгрузок)
npm run download     # выгрузки Tatoeba + словарь HSK в tools/.cache (~45 МБ, распакованно ~250 МБ)
npm run select       # отбор предложений Tatoeba → sentences/picks.json
npm run build        # сборка data/sentences-N.json + списки дел в .cache/todo/
npm run show -- 好 学 会    # посмотреть, что получилось у знаков
```

`download` нужен один раз (и когда хотите свежую Tatoeba). `select` — когда меняли правила или
хотите подобрать замены отбракованным; `build` — после любой правки в `sentences/`.

## Правила отбора

У каждого знака 2–3 предложения, не длиннее 12 иероглифов, только китайские знаки и пунктуация.

- **HSK 1** — по урокам HSK Standard Course 1 (списки уроков берутся из `index.html`):
  пример к знаку из урока N состоит только из знаков уроков 1…N.
- **HSK 2–6** — все слова из HSK уровня знака или ниже: слово из HSK 2.0 этого уровня, либо
  слово из HSK 3.0 этого уровня, все иероглифы которого уже есть в приложении к этому уровню
  (в списке HSK 2.0 нет даже 天, 一些, 春天).
- Приоритет у предложений Tatoeba с русским переводом, затем Tatoeba с английским (перевод наш),
  затем составленные нами (в приложении помечены «составлено»).
- Уже отобранные предложения при повторном `select` сохраняются, чтобы не терять переводы.

## Что лежит в `sentences/` (это наши данные, они в git)

| Файл | Формат | Зачем |
|---|---|---|
| `picks.json` | — | результат `select`, не править руками |
| `translations/*.tsv` | `id⇥русский перевод` | переводы предложений Tatoeba, у которых нет русского |
| | `id⇥SKIP` | предложение Tatoeba не использовать (грубое, кривое, с именами…) |
| `composed/*.tsv` | `знак⇥предложение⇥перевод` | свои предложения; `!знак` в начале — показать первым |
| `../hsk1/items.tsv` | см. шапку файла | HSK 1: слово-пример с переводом, «В уроке», состав, подсказка, исправления пиньиня/аудио; `npm run hsk1` переносит в `index.html` |
| `exclude.txt` | одно предложение на строку | никогда не использовать (например, реплики из учебника) — **файл локальный, в git не попадает** |

Строки, начинающиеся с `#`, — комментарии. Номер `id` — это номер на tatoeba.org.

`exclude.txt` указан в `.gitignore`: в нём реплики из учебника HSK Standard Course, которым не место
в публичном репозитории. Он есть только на том компьютере, где его создали. Без него сборка тоже
работает, но фразы из учебника могут вернуться в примеры — перед `select`/`build` на новом
компьютере создайте файл заново (формат — одна фраза на строку, `#` — комментарий).

## Как дополнять

1. `npm run build` — в конце он пишет, сколько осталось дел, и кладёт списки в `.cache/todo/`:
   - `translate-*.tsv` — предложения без перевода (`id⇥китайский⇥английский`): переведите и
     допишите `id⇥перевод` в новый файл `translations/NN.tsv` (или `id⇥SKIP`);
   - `compose-*.tsv` — знаки, где меньше 2 примеров: в подсказке для HSK 1 перечислены
     разрешённые знаки урока, для HSK 2–6 — подходящие слова. Допишите строки в `composed/`.
2. Снова `npm run build`. Составленные предложения, которые не прошли правила, он перечислит
   с причиной («урок 3: 请 not yet taught», «level 5 > 3», «13 han» …).
   `node build.mjs --prune` удалит такие строки из `composed/`.
3. Не понравился пример из Tatoeba — `npm run show -- 知` покажет его `#id`;
   допишите `id⇥SKIP` в `translations/`, затем по очереди `npm run select` и `npm run build`.
4. Проверьте шрифт: `npm run font-gap`. Если появились новые знаки — `npm run fonts`, потом
   сверить список шрифтов в `sw.js` и поднять `SHELL_VERSION`.

Пиньинь — `pinyin.mjs`, общий для предложений и слов-примеров HSK 1 (поэтому они совпадают).
Слоги ставит pinyin-pro, дальше правила в духе учебника Standard Course:
- слова слитно по словарю HSK (`zàijiàn`, `xuésheng`), числа одним словом (`shí'èr`, `sānshíyī`),
  `xīngqīyī`, `yíxià`, `kànkan`; лёгкий тон — из словаря;
- раздельно (`NO_GROUP`): глагол + дополнение (`dǎ diànhuà`, `huí jiā`, `xià yǔ`), `bú duì`,
  `bú kèqi`, `méi guānxi`; A不A — `shì bu shì`, `yǒu méiyǒu`; результативные — `kàn bu jiàn`;
- контекст (`CONTEXT`): 再 见面, 二十 分, 十 分钟, 一 个 人; `CLAUSE_START_ONLY`: 再说;
- многочтения отдельно стоящих знаков (`polyphone`): 个 → ge, 谁 → shéi, 里 → li, 得, 地, 只,
  长, 为, 了, 着, 还, 不; тоны 一 и 不 — как произносятся (`yí ge`, `bú huì`).
Нашли неверное написание — добавьте слово или правило в таблицы в начале `pinyin.mjs`.

## Раздел «Речь»: диалоги и опорные фразы

`npm run speech` собирает `speech/hskN.txt` → `data/speech-N.json` (пиньинь ставит тот же `pinyin.mjs`).
`node speech.mjs --show 3 5 6` печатает собранные уроки для вычитки.

Формат `speech/hskN.txt` описан в шапке файла: `= N` — урок, `== Д: название` — диалог с репликами
`A: китайский | перевод`, `== Ф: название` — схема (`Q` — вопрос, `A` — 2–3 ответа, `R` — что заменять,
`S` — подстановки). Сборка не запишет файл, если:

- в уроке HSK 1 встретился знак не из уроков 1…N;
- диалогов не 2–3 или схем не 5–10; в схеме не 2–3 ответа;
- в реплике есть слово не из словаря уроков 1…N (`sentences/vocab.txt` — **локальный файл, как `exclude.txt`**: строка
  «урок: слова через пробел», части слова в скобках, имена после `|`; без файла эта сверка пропускается).
  Очевидные составные слова (`我们`) и исключения — таблица `OBVIOUS` в `speech.mjs`; `node speech.mjs --vocab`
  печатает только слова вне словаря;
- слово или грамматика встретились раньше урока, где их вводит учебник (таблица `TOO_EARLY` в `speech.mjs`:
  номера уроков взяты из оглавления учебника; нашли новую ошибку — допишите правило туда);
- две реплики подряд совпали с `sentences/exclude.txt` (то есть скопирован обмен репликами из учебника).

Отдельные совпадения с `exclude.txt` — ключевые формулы урока (`你叫什么名字？`) — сборка только перечисляет.
Формулы до трёх знаков (`你好`, `谢谢你`) не считаются. Имена героев и их пиньинь — таблица `NAMES` в `speech.mjs`.
Новый уровень: добавить `speech/hskN.txt` и номер уровня в `SPEECH_IDS` в `index.html`.

## Громкость записей слогов

`data/audio-N.json` — записи слогов (mp3 в base64). Их громкость выровнена скриптом `audio-gain.py`:
он сдвигает поле `global_gain` в кадрах mp3 (шаг 1,5 дБ), без перекодирования — качество и размер
файлов не меняются. Нужен Python с `numpy` и `imageio-ffmpeg` (ffmpeg только измеряет уровень).

```
python tools/audio-gain.py          # показать, что изменится
python tools/audio-gain.py --write  # записать
```

После записи поднимите `DATA_VERSION` в `sw.js` и `DATA_CACHE` в `index.html`.

## Озвучка фраз нейросетевым голосом

`data/voice-N.json` и `data/voice-N-УУ.mp3` — диалоги, опорные фразы, слова и примеры предложений уровня,
прочитанные моделью Kokoro-82M-v1.1-zh (голос `zf_017`, скорость 0,9). Указатель `voice-N.json` хранит для
каждого текста урок, смещение и длину в файле урока; файл урока — mp3 всех его фраз подряд (моно, 24 кГц,
32 кбит/с). Текст попадает в файл первого урока, где он встретился. Всё, чего в указателе нет, читает
синтез речи телефона.

```
pip install torch kokoro "misaki[zh]" soundfile numpy imageio-ffmpeg   # один раз; с видеокартой быстрее
python tools/voice.py 1 --check   # сверить чтение модели с пиньинем из данных
python tools/voice.py 1           # озвучить новые тексты и пересобрать файлы уровня
```

Запускать после изменения `data/speech-N.json`, `data/sentences-N.json` или слов уровня. `--check` печатает
фразы, где тоны модели расходятся с пиньинем данных; расхождения в нейтральном тоне (后面, 这里, 哪个)
допустимы. Если модель читает знак неверно, впишите в `voice-fixes.json` тот же текст в написании,
которое она читает правильно (например, с пробелом между словами). Готовые wav лежат в `.cache/voice`.
После пересборки поднимите `VOICE_VERSION` в `sw.js` и `VOICE_CACHE` в `index.html`. Новый уровень —
добавить его номер в `VOICE_IDS` в `index.html`.

## Карточки знаков HSK 1: из чего состоит и как запомнить

`npm run hints` собирает `hints/hsk1.tsv` → `data/hints-1.json`. В файле по строке на каждый знак HSK 1:
знак, разбор Make Me a Hanzi (`⿰女子`, по первому знаку — «слева направо», «сверху вниз»…), части
с русскими значениями и одна короткая строка. Вид строки: `о` — происхождение (рисунок или сочетание
по смыслу, как объясняют словари), `з` — происхождение «смысл + звук», `п` — придуманная подсказка
(в приложении с пометкой «Подсказка, не история знака»). Формат подробно — в шапке файла.
Туда же идут похожие знаки из `hints/similar.txt` (группы по 2–4 знака: «знак ⇥ чем отличается», между
группами пустая строка); в «Повторе» группа появляется, когда пройден хотя бы один её знак.
Сборка проверяет, что строка есть у каждого знака HSK 1 и только одна. Файл входит в оболочку
(`sw.js`, `SHELL_FILES`): после правки — `SHELL_VERSION += 1`; новые знаки в текстах — `npm run font-gap`.
